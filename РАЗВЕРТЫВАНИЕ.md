# 🚀 Развертывание веб-сервиса в Production

## ❓ Что это значит?

**Production** = размещение вашего веб-сервиса на сервере в интернете, чтобы Zoho CRM мог к нему обращаться.

**Сейчас:** Сервис работает только у вас на компьютере (`localhost:5000`)  
**Нужно:** Сервис должен быть доступен по адресу типа `https://your-service.com`

---

## 🎯 Что у вас есть и как использовать

### ✅ GitHub (у вас уже есть)
- **Для чего:** Хранить код проекта
- **Что делать:** Загрузите код в репозиторий

### ⚠️ Netlify (для статических сайтов)
- **Проблема:** Netlify не подходит для Flask напрямую
- **Решение:** Используйте Railway или Render (см. ниже)

### ⚠️ Supabase (база данных)
- **Для чего:** База данных (нам не нужна для этого проекта)
- **Решение:** Не используется для веб-сервиса звонков

---

## ✅ Рекомендуемое решение: Railway.app

**Почему Railway:**
- ✅ Бесплатный план (500 часов/месяц)
- ✅ Автоматическое развертывание из GitHub
- ✅ Автоматический HTTPS
- ✅ Очень простая настройка

### 📋 Пошаговая инструкция:

1. **Зарегистрируйтесь на Railway:**
   - Перейдите: https://railway.app
   - Нажмите "Login" → "Login with GitHub"
   - Разрешите доступ к вашему GitHub

2. **Создайте новый проект:**
   - Нажмите "New Project"
   - Выберите "Deploy from GitHub repo"
   - Выберите ваш репозиторий с кодом

3. **Настройте переменные окружения:**
   - Откройте Settings → Variables
   - Добавьте переменные:
     ```
     TIKAL_BASE_URL = http://arielsip.com
     TIKAL_API_KEY = c18950499e5838743873737478ff1de9
     TIKAL_FORMAT = json
     PORT = 5000
     ```

4. **Настройте команду запуска:**
   - Settings → Deploy
   - Start Command: `python zoho_call_service_production.py`

5. **Deploy:**
   - Railway автоматически начнет развертывание
   - Подождите 2-3 минуты
   - Получите URL типа: `https://your-app.up.railway.app`

6. **Проверьте:**
   - Откройте URL в браузере
   - Добавьте `/health` в конце: `https://your-app.up.railway.app/health`
   - Должен вернуться JSON с `"status": "ok"`

7. **Обновите Zoho:**
   - В Zoho Workflow измените URL на ваш Railway URL
   - Вместо `http://localhost:5000` используйте `https://your-app.up.railway.app`

## 📁 Что нужно загрузить в GitHub

### ✅ Загрузите:
- `zoho_call_service_production.py` (новая версия для production)
- `tikal_client/` (папка с клиентом)
- `requirements.txt`
- `Procfile`
- `runtime.txt`

### ❌ НЕ загружайте:
- `config.py` (содержит секреты)
- `*.bat` файлы (не нужны на сервере)
- `*.csv` файлы (если не нужны)

## 🔐 Безопасность

**ВАЖНО:** Не загружайте `config.py` в GitHub!

Вместо этого используйте переменные окружения на Railway:
- `TIKAL_API_KEY` - ваш API ключ
- `TIKAL_BASE_URL` - адрес сервера Tikal

## 🧪 Тестирование после развертывания

1. **Проверьте health endpoint:**
   ```
   https://your-app.up.railway.app/health
   ```

2. **Проверьте создание звонка:**
   - Используйте Postman или curl
   - POST запрос на `/api/call/create`
   - С телом: `{"agent_id":"6701","phone_number":"0508155492"}`

3. **Проверьте в Zoho:**
   - Откройте контакт
   - Нажмите кнопку "Позвонить"
   - Проверьте логи в Railway Dashboard

## 🆘 Решение проблем

### Сервис не запускается
- Откройте Railway Dashboard → Logs
- Проверьте ошибки в логах
- Убедитесь, что все переменные окружения установлены

### Zoho не может подключиться
- Проверьте, что URL использует HTTPS (не HTTP)
- Проверьте CORS настройки (уже настроено в коде)
- Проверьте firewall настройки Railway

### Ошибки импорта
- Убедитесь, что все файлы загружены в GitHub
- Проверьте структуру проекта
- Проверьте `requirements.txt`
