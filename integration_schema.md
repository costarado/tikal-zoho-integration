## Компоненты системы

### 1. Authentication Manager
**Назначение:** Управление токенами доступа и автоматическое обновление

**Функции:**
- Хранение access_token и refresh_token
- Автоматическое обновление токена при истечении
- Проверка валидности токена перед запросами
- Обработка ошибок аутентификации

**Механизм работы:**
1. При инициализации использует предоставленные токены
2. Перед каждым API запросом проверяет валидность access_token
3. При получении 401 ошибки автоматически обновляет токен через refresh_token
4. Сохраняет новые токены для последующих запросов

### 2. API Service Layer
**Назначение:** Высокоуровневый интерфейс для работы с API

**Модули:**
- **CallsService** - управление звонками
  - Получение списка звонков
  - Получение деталей звонка
  - Создание исходящего звонка
  - Фильтрация по датам, агентам, статусам

- **RecordingsService** - работа с записями
  - Получение списка записей
  - Скачивание записей
  - Связь записей со звонками

- **AgentsService** - управление агентами
  - Получение списка агентов
  - Получение информации об агенте
  - Статусы агентов

- **StatisticsService** - статистика
  - Статистика по звонкам
  - Статистика по агентам
  - Отчеты за период

### 3. Error Handler & Retry Logic
**Назначение:** Обработка ошибок и повторные попытки

**Стратегии:**
- Retry при временных ошибках (5xx, network errors)
- Exponential backoff для повторных попыток
- Логирование всех ошибок
- Уведомления о критических ошибках

## Поток данных

### Типичный запрос:
```
1. Application → TikalClient.method()
2. TikalClient → AuthManager.check_token()
3. AuthManager → (если нужно) refresh_token()
4. TikalClient → APIRequest с токеном
5. TikalAPI → Response
6. TikalClient → Parse & Return Data
7. Application → Use Data
```

### Обновление токена:
```
1. API Request → 401 Unauthorized
2. Error Handler → Catch 401
3. AuthManager → POST /api/auth/refresh
4. AuthManager → Save new tokens
5. Retry original request with new token
```

## Безопасность

1. **Хранение токенов:**
   - Токены хранятся в памяти во время работы
   - Для production рекомендуется использовать secure storage (environment variables, secrets manager)

2. **HTTPS:**
   - Все запросы только через HTTPS
   - Проверка SSL сертификатов

3. **Логирование:**
   - Токены не логируются
   - Логируются только метаданные запросов

## Расширяемость

Система спроектирована для легкого добавления новых endpoints:
1. Создать новый сервис в `services/`
2. Наследоваться от базового класса
3. Реализовать методы API
4. Зарегистрировать в основном клиенте
